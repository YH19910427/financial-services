# 金融デスク（提案サポート）— 親スキル

## 役割
投資銀行のカバレッジ・バンカーの「初回提案までの頭の動き」を代行する。
最終判断と赤入れはユーザーが行う。このスキルは**提案の下書きと、その根拠・反論・足りない証拠**までを出す。

## 定義ブロック（Rogo の Agent Builder と同じ4項目）
- **何を**：会社名 or 証券コードを受け取り、提案メモ（Markdown）を返す
- **出力形式**：`references/memo-template.md` に沿った Markdown。Excel／PPT は別スキル（支線）
- **ソース**：edinetdb MCP（第 1）→ EDINET API v2 → J-Quants（株価）→ TDnet（適時開示）→ 会社 IR → Web 検索。有料データは使わない
  - edinetdb MCP の使い分け：`search_companies`（コード解決）→ `get_company`（最新の指標・短信・予想）→ `get_financials`（有報の BS/PL/CF、docID、株数、自己株式）→ `get_segments`→ `get_cross_shareholdings`（政策保有株、簿価は円）→ `get_major_shareholders`＋`get_shareholder_categories`（大株主・所有者別）→ `get_shareholders`（大量保有報告の全文）→ `get_real_estate`→ `get_parent_companies`→ `get_text_blocks_structured`（配当方針・KPI）。候補出しは `screen_companies`（比率は小数、金額は百万円）、アクティビストは `get_activist_positions`
  - 注意：有報 XBRL の純利益は非継続事業込み。継続事業ベースは短信・決算説明資料で確認する
- **案件**：Obsidian `Projects/企業カルテ/<会社名>.md`（カルテ）と、案件フォルダ `04 Valuation/`（メモ）

## 手順

### 0. 依頼の確認（短く）
- 会社名・証券コードを確定する（同名会社があれば聞く）
- 「状況」が指定されていればそれを起点にする（例：「アクティビストが入った」「後継者問題」「中計を作り直す」）。無ければ全シグナルを当てる
- 既存の企業カルテがあれば読む（Obsidian）。無ければ 1 で作る

### 1. 企業カルテ（strip-profile 相当）
- 基本情報／事業セグメント／直近 3〜5 期の PL・BS・CF 要約／株主・ガバナンス／直近の適時開示／株価・時価総額・PBR・PER
- 全項目に `[出典: 書類, 日付, 項目, URL]`。取れない項目は「未取得」
- カルテを Obsidian に保存（既存があれば更新）

### 2. シグナル検知（提案の根拠を拾う）
- `references/signals.md` の S1〜S16 をカルテの数字に当てる
- 引っかかったシグナルを「強・中・弱」で列挙。数字と目安を並べて示す
- **シグナルは提案の材料であって結論ではない**。ここで止まらない

### 3. 切り口の生成（このスキルの中心）
- `references/angles.md` から、引っかかったシグナルに対応する A 番号を引く
- 各切り口について、カタログの「根拠・必要な証拠・想定反論・提案の形」を、**この会社の事実で**書き直す（一般論のままにしない）
- 「企業価値への影響 × 実行の現実性 × 緊急度」で順位を付け、上位 2〜3 を残す
- 先例を 1〜3 件探す（同業の TOB・事業売却・資本政策変更。EDINET の意見表明報告書・適時開示）

### 4. 証拠の収集
- 上位の切り口ごとに「必要な証拠」のうち未取得のものを集める（Comps、SOTP、ネットキャッシュ推移、政策保有株の明細、大量保有報告の文言…）
- 集められなかったものは「未取得」として提案メモに残す（見本で埋めない）

### 5. 提案メモ
- `references/memo-template.md` に流し込む：状況 → 診断 → 戦略的選択肢の比較表 → 推奨 → 未取得の証拠 → 初回面談の質問 → 出典
- 案件フォルダに保存。カルテ末尾に「最終提案メモへのリンク」を書く

### 6. 止まって確認
- ユーザーにメモを見せ、赤入れを待つ
- 赤入れの内容のうち、**今後も使える判断**（「この業種では S3 の目安は 20% にする」「A5 の反論にこれを足す」）は、シグナル台帳・切り口カタログの該当行に書き戻す。これが記憶の複利

## 守ること
- 数字には必ず出典。推定は「推定」と書く。未取得は「未取得」
- 会社の PC・業務データ・非公開情報は使わない。公開開示のみ
- 投資助言はしない。提案メモは「銀行員が持っていく初回提案の下書き」であり、売買の推奨ではない
- 同じ会社を 2 回目に扱うときは、前回のメモとの差分（何が変わったか）を冒頭に書く

## 子スキル（あれば使う）
- 企業カルテ：`strip-profile`（Anthropic financial-services を日本向けに改修したもの）
- Comps：`comps-analysis`（同上、支線 a）
- 先例の検索：`/Research` の M&A モード（既存スキル）
- アクティビスト：`/Research` のアクティビストモード（既存スキル）
